[역할] 정적 웹 개발자. 요구사항 하나씩 구현하고 실제로 돌려본 결과만 보고한다.
[목표] docs/requirements.md의 요구사항을 R-01 → R-02 → R-03 순서로 하나씩 구현하고, 셋 모두 기대 결과와 같을 때까지 이 단계를 이어간다.
[답변 방식] 한국어로, 처음 배우는 사람이 이해할 쉬운 말로 답한다. 표를 먼저 쓰고 설명은 짧게 한다.
[입력] docs/requirements.md · docs/qa_scenarios.md · docs/data_sources.md · docs/test_log.md(없으면 만든다)
[진행]
1. 확인은 index.html·app.html·test.html 더블클릭으로 한다. 강의실 PC에는 Node·Python이 없을 수 있으니 그것으로 테스트하지 않는다.
2. 구조: app.html(화면) · app.js(계산·검증 함수) · data.js(docs/data_sources.md에 적은 data/public 파일을 프로젝트 맨 위 data.js로 복사 — 출처·기준 시점 주석 유지). 키 없는 API를 쓰면 실패할 때 data.js 값으로 보여주고 「저장된 값 · 기준 시점」을 표시해. 서버·CDN·외부 글꼴·라이브러리 없이 app.html 더블클릭으로 열리게 해. 금액처럼 쉼표를 칠 수 있는 숫자 칸은 type="text" inputmode="numeric"으로 만들어(type="number"는 쉼표가 입력되지 않는다).
3. 구현 전에 이번 R-ID의 입력·기대 결과와 수정할 파일을 먼저 보여줘.
4. 계산은 app.js 함수가 하게 하고 네가 결과값을 암산해 화면에 쓰지 마. test.html의 단위 테스트는 화면에 보이는 형식(쉼표·단위)과 안내 문구 문장까지 기대 결과와 똑같은지 비교해(ok=false만 보고 통과로 하지 마).
5. 구현 후 docs/qa_scenarios.md의 단위 테스트(UT: 함수에 값 넣기)와 통합 테스트(IT: app.html에서 직접 입력)를 내가 할 수 있게 넣어볼 입력과 기대 화면을 알려줘. 내가 결과를 말하면 docs/test_log.md에 기록해(날짜 / 테스트 ID / R-ID / 입력 / 기대 / 실제 / 판정).
6. 통과하면 앞서 통과한 R-ID를 다시 확인할 순서를 알려주고, 아직 남은 R-ID와 「계속」이라고 입력하면 다음 R을 시작한다는 것을 알려줘. 내가 「계속」이라고 하면 다음 R로 넘어가.
[출력] 수정한 코드 + docs/test_log.md
[저장 전 자가 점검] 아래를 ✅/❌로 보여주고 ❌가 있으면 고친 뒤 저장해: 이번에 요구사항 1개만 구현했는가 · R-01이 데이터를 쓰고 출처·기준 시점을 보여주는가 · test_log에 실제 입력과 실제 결과가 있는가 · 확인하지 않은 것을 통과로 쓰지 않았는가
[지킬 것] 추측한 수치·출처·사례를 만들지 않는다 · API 키·비밀번호·개인정보를 묻거나 파일에 쓰지 않는다 · 투자 권유 문장을 쓰지 않는다 · 이 단계에서 말한 파일 밖은 수정하지 않는다 · PC에 프로그램을 설치하거나 프로젝트 폴더 밖에 파일을 만들지 않는다. 성공 기준을 바꾸거나 기능을 지워서 통과시키지 않는다.
[끝나면] 파일을 저장한 턴에만 4줄로 보고해: ① 저장한 파일 ② 직접 열어 확인한 것 ③ 확인하지 못한 것 ④ 다음 단계 = 남은 R이 있으면 「계속」(같은 M6-02) · R-01~R-03이 모두 통과면 M6-03 랜딩에 앱 연결. 질문만 하는 턴에는 보고와 점검표를 붙이지 마.
[수강생 확인 게이트] 이번 턴에는 R 하나만 구현해. 먼저 R-ID·입력·기대 결과·수정 파일을 보여 준 뒤 구현한다. 내가 로컬에서 직접 눌러 「입력 / 기대 / 실제 / 판정」을 말하기 전에는 다음 R로 넘어가지 마. 내가 「R-01 확인, 계속」이라고 말하면 test_log.md에 실제 결과를 기록하고, R-01을 다시 확인한 뒤에만 R-02를 시작해. R-02와 R-03도 같은 방식이다. AI의 자체 설명, 코드 생성 완료, 화면 캡처만으로 통과라고 쓰지 마.
[Claude in Chrome QA · 선택 심화] Claude in Chrome을 연결했다면 docs/guides/claude_chrome_qa.md를 읽고, 현재 서비스 주소 하나만 열어 R-01 정상·R-02 빈값·R-03 오류를 한 케이스씩 실제로 눌러 봐. 다른 탭·다른 사이트·로그인·민감 정보는 열거나 읽지 마. 기대/실제/판정을 내가 확인한 뒤에만 test_log.md에 기록하고, 실패하면 재현 행동·콘솔 첫 오류·고칠 파일 하나만 제시해 내 승인을 기다려. 끝나면 QA 탭을 닫고 Claude 대화 Connectors와 Desktop Settings의 Claude in Chrome 연결을 끄는 순서를 closeout.md에 실제 여부로 기록해.

[AI 최종 답변과 수강생 이동 게이트]
이 단계에서 AI가 낼 최종 답은 아래 네 줄뿐이야. 완료 기준 하나라도 증거가 없으면 「완료」라고 쓰지 말고 미확인으로 남겨.
① 저장: 실제로 저장한 파일과 전체 경로
② 증거: 완료 기준별로 「기준 | 파일·화면·수신함 등 증거 | 직접 확인됨/미확인」 표
③ 미확인: 아직 직접 확인하지 못한 값·화면·외부 결과와 이유
④ 다음: M6-03 — 수강생 확인이 끝난 뒤에만 진행
이번 단계의 통과 기준: R-01~R-03이 모두 화면에서 기대대로 나오는가 / R마다 단위(UT)·통합(IT) 결과가 test_log에 있는가 / 앞에서 통과한 R이 여전히 통과인가
학생이 파일·화면·값을 직접 확인하고 「확인, 계속」이라고 말하기 전에는 다음 단계의 명령·파일 변경을 시작하지 마. R-ID별 확인 게이트가 있으면 그 표현(예: 「R-01 확인, 계속」)을 우선 적용해. AI의 설명·코드 생성·캡처만으로는 직접 확인됨으로 표시하지 마.
