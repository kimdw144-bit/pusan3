# 요구사항 기반 단위·통합 테스트 설계서

**M5 구현 전에 설계하고, 구현할 때마다 실행합니다. M6까지 기다리지 않습니다.** 실제 결과와 통과 여부는 실행한 뒤 `test_log.md`에 기록합니다. 미실행은 통과가 아닙니다.

단위 테스트(UT): 입력 검사·계산·변환 같은 작은 동작 하나를 확인합니다. 통합 테스트(IT): 데이터 읽기·처리·화면·API 등 연결된 부분이 함께 동작하는지 확인합니다. 별도로 사용자 전체 흐름도 로컬과 배포 주소에서 확인합니다.

교육용 예시: 뉴스 목록 기능에서 빈 기사 배열을 처리하는 함수가 안내 결과를 반환하는지(UT), 빈 응답을 공급했을 때 브라우저에 안내가 나오고 이전 기사가 남지 않는지(IT). 이 예시를 자기 기능에 맞게 바꿉니다.

> 요구사항 명세의 각 R-ID에 대응하는 단위·통합 테스트 설계서를 만들어줘. 입력·사전 조건·실행 순서·기대 결과를 명시하고, 외부 API 모의 응답과 실제 연결 검사를 구분해줘. 요구사항에서 기대값을 도출하고 구현 결과를 보고 기대값을 바꾸지 마. 현재 프로젝트에서 실행 가능한 테스트 방법을 정하되 실제 결과는 비워둬.

QA는 명세와 테스트의 누락·설명·오류 처리도 함께 점검합니다. 테스트 통과 수만으로 사용자 문제나 사업 가설이 검증됐다고 하지 않습니다.
