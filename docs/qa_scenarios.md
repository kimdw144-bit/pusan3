# 요구사항 기반 단위·통합 테스트 설계서

**M5 구현 전에 설계하고, 구현할 때마다 실행합니다. M6까지 기다리지 않습니다.** 실제 결과와 통과 여부는 실행한 뒤 `test_log.md`에 기록합니다. 미실행은 통과가 아닙니다.

단위 테스트(UT): 입력 검사·계산·변환 같은 작은 동작 하나를 확인합니다. 통합 테스트(IT): 데이터 읽기·처리·화면·API 등 연결된 부분이 함께 동작하는지 확인합니다. 별도로 사용자 전체 흐름도 로컬과 배포 주소에서 확인합니다.

## 단위 테스트

|테스트 ID|요구사항 ID|대상 함수·동작|입력·사전 조건|기대 결과|실행 방법·명령|
|---|---|---|---|---|---|
|UT-01|R-01|`calcDepositVsInflation(rows, start, end)`|2021년(예금1.197,물가2.498)·2025년(예금2.734,물가2.123) 두 행만 담은 테스트 배열, start=2021,end=2025|2021년 격차 −1.301(마이너스로 판정), 2025년 격차 0.611(플러스), 마이너스 연도 수=1 반환|브라우저 콘솔에서 `calcDepositVsInflation(testRows,2021,2025)` 호출 후 반환값 확인|
|UT-02|R-02|`validateRange(start, end)`|start=null, end=2025|"비교할 기간을 선택하세요" 메시지 반환(계산 진행 안 함)|콘솔에서 `validateRange(null,2025)` 호출 후 반환값 확인|
|UT-03|R-03|`validateRange(start, end)`|start=2025, end=2016(역순 입력)|"기간을 다시 확인해주세요" 오류 메시지 반환(계산 진행 안 함)|콘솔에서 `validateRange(2025,2016)` 호출 후 반환값 확인|

## 통합 테스트

|테스트 ID|요구사항 ID|연결 대상|사전 조건・입력|실행 순서|기대 결과|모의/실제 연결 구분|
|---|---|---|---|---|---|---|
|IT-01|R-01|data.js 로드 + 화면 렌더링|`app.html`을 브라우저에서 열고 기본 기간(2021~2025) 유지|① 페이지 로드 ② 기본 기간 자동 적용 ③ 결과 영역 확인|마이너스 연도 수와 한국 주가지수 최고~최저 수익률 범위가 숫자로 표시되고 출처·기준 시점 문구가 보임|실제 연결(정적 data.js, fetch 없음)|
|IT-02|R-02|기간 선택 UI|기간 드롭다운을 "선택 안 함" 상태로 둠|① 페이지 로드 ② 기간 미선택 상태에서 "확인" 클릭 ③ 결과 영역 확인|"비교할 기간을 선택하세요" 안내만 보이고 계산 결과 영역은 비어 있음|실제 연결|
|IT-03|R-03|잘못된 기간·데이터 로드 실패 처리|① 시작연도를 종료연도보다 늦게 선택 ② (수동) `data.js` 파일명을 일시적으로 바꿔 로드 실패 재현|① 잘못된 기간 선택 후 "확인" 클릭 ② data.js 로드 실패 상태에서 페이지 새로고침|① 오류 안내 문구 표시, 이전 결과 남지 않음 ② "데이터를 불러오지 못했습니다" 문구 표시, 화면 깨지지 않음|실제 연결(②는 파일명 임시 변경으로 오류 상황을 의도적으로 재현)|

교육용 예시: 뉴스 목록 기능에서 빈 기사 배열을 처리하는 함수가 안내 결과를 반환하는지(UT), 빈 응답을 공급했을 때 브라우저에 안내가 나오고 이전 기사가 남지 않는지(IT). 이 예시를 자기 기능에 맞게 바꿉니다.

> 요구사항 명세의 각 R-ID에 대응하는 단위·통합 테스트 설계서를 만들어줘. 입력·사전 조건·실행 순서·기대 결과를 명시하고, 외부 API 모의 응답과 실제 연결 검사를 구분해줘. 요구사항에서 기대값을 도출하고 구현 결과를 보고 기대값을 바꾸지 마. 현재 프로젝트에서 실행 가능한 테스트 방법을 정하되 실제 결과는 비워둬.

QA는 명세와 테스트의 누락·설명·오류 처리도 함께 점검합니다. 테스트 통과 수만으로 사용자 문제나 사업 가설이 검증됐다고 하지 않습니다.
