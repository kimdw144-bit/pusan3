# 사업 기획 — Lean Canvas 9칸 · 근거에서 가설로

Lean Canvas는 사업계획서의 축약판입니다. **문제·고객·고유 가치 제안** 세 칸이 중심이며, 나머지 여섯 칸은 이 세 가지를 실제 서비스로 만들고 검증하는 설계입니다. 이 순서로 쓰는 이유는 고객과 문제가 틀리면 기능·채널·수익을 아무리 자세히 적어도 검증할 대상이 사라지기 때문입니다.

## 작성 원칙

- 각 칸은 한 문장으로 시작하되, 반드시 **근거 또는 가설**, **다음 확인 질문**을 붙입니다.
- `[사실]`은 직접 연 원문 링크·자료명·기준일이 있어야 합니다. 없으면 `[가설]` 또는 `[리서치 필요]`입니다.
- AI가 시장 규모·고객 수·매출·경쟁 사례를 만들어 채우지 않게 합니다.
- TAM → SAM → SOM은 같은 제품 범위·고객 집단·기간을 써야 비교됩니다. SOM은 채널과 실제 운영 역량으로 좁힙니다.

> 내 아이디어로 Lean Canvas 9칸 초안을 만들어줘. `docs/topic.md`와 `docs/data_sources.md`의 내용을 먼저 읽고, 문제 → 초기 고객 → 고유 가치 제안 세 칸은 한 칸씩 나에게 질문해 확인받은 뒤 다음 칸으로 가. 각 칸은 `내 한 문장 / 사실·가설 / 확인한 근거 링크·자료명·기준일 또는 리서치 필요 / 다음 확인 질문` 네 요소를 가진 표로 써. 자료에 없는 시장 규모·고객 수·매출은 만들지 말고 가설로 표시해. TAM·SAM·SOM은 제품 범위·고객·기간이 같은 경우에만 쓰고, SOM은 채널과 운영 역량으로 한정해. 가장 위험한 가정 하나에는 ★를 붙여 `docs/lean_canvas.md`에 저장해. 아직 구현하지 마.

다음: 고객 칸의 첫 고객을 `persona.md`의 한 사람으로 그리고, `journey_map.md`에서 그 사람의 목표로 가는 길을 그립니다.
