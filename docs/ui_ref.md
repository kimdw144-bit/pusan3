# UI 참고 — 토스의 원칙만 가져오기 (M6-01)

> **원칙만 참고합니다.** 토스 로고·아이콘·글꼴·이미지·화면 캡처는 내 앱에 넣지 않습니다.

## 가져올 원칙 3가지

|원칙|내 랜딩·앱에서|
|---|---|
|한 화면(한 섹션)에 한 메시지|섹션마다 제목 한 줄 + 핵심 문장 하나|
|핵심 숫자는 크게|결과 금액·비율을 가장 큰 글자로, 설명은 작게|
|누를 것은 크고 분명하게|버튼 하나 · 버튼 글자는 동사로(「계산하기」「시연 보기」)|

그 밖에: 넉넉한 여백 · 색은 한두 가지 · 질문에 답하기 쉬운 순서(토스는 이를 「Easy to answer」라고 부릅니다).

## 직접 열어 볼 공개 자료 (링크만)

- 토스 디자인 원칙 사례 «Easy to answer»: https://toss.tech/article/insurance-claim-process
- toss.tech 디자인 글 모음: https://toss.tech/design
- 토스 디자인 시스템 공개 문서(TDS Mobile): https://tossmini-docs.toss.im/tds-mobile/
- 토스 디자인 컨퍼런스 Simplicity: https://toss.im/simplicity

강의실에서 강사가 보여주는 토스 앱 화면은 **구성을 보는 참고용**이며 내려받거나 복제하지 않습니다.

## 랜딩은 왜 시각 요소가 필요한가

랜딩은 예쁜 소개문이 아니라, 처음 온 사람이 **무슨 문제를 누구를 위해 어떻게 줄이는지** 30초 안에 이해하고 시연을 누르게 하는 화면입니다. 따라서 글만 나열하지 않고 다음 다섯 요소를 반드시 넣습니다.

| 요소 | 사용자에게 답하는 질문 | 원본으로 만드는 방법 |
|---|---|---|
| Hero + CTA | 무엇이고, 누구를 위한가 | 한 줄 가치 제안 + 큰 버튼 + CSS 도형/SVG |
| 데이터 카드·미니 차트 | 왜 지금 이 문제가 중요한가 | 숫자 2개·기간·출처·한계를 담은 차트 |
| 전·후 흐름 | 기존보다 무엇이 쉬워지나 | 기존 대안 → F-01 → 사용자 결과의 3단계 도형 |
| 앱 미리보기 | 누르면 실제로 무엇을 하나 | 내 `app.html`의 입력·결과 화면 또는 원본 와이어프레임 |
| 한계·신뢰 | 무엇을 하지 않으며, 무엇을 확인했나 | 테스트 수·데모 범위·출처 고지 카드 |

## UI 참고를 Claude Code에 요청하는 법

```text
내 서비스의 랜딩과 앱 UI를 설계하려고 해.
docs/ui_ref.md와 docs/ui_design.md를 읽고, 공개 자료에서는 정보 위계·입력 순서·오류 안내 원칙만 참고해줘.
타사 로고·글꼴·이미지·화면을 복제하지 말고, 내 데이터와 원본 CSS/SVG로 Hero·데이터 카드/차트·전후 흐름·앱 미리보기·CTA·한계 고지의 6요소를 설계해줘.
각 요소가 어느 docs 문장에서 왔는지와, R-01·R-02·R-03에서 사용자가 무엇을 보게 되는지 표로 보여준 뒤 docs/ui_design.md에 저장해줘.
```

## 수업용 관찰용 레퍼런스 캡처 · 관찰은 하고 복제하지 않기

공개 서비스 화면을 직접 보면서 정보 위계·버튼 위치·입력 순서를 관찰하는 것은 가능합니다. 수업에서는 **본인이 직접 캡처한 화면**을 `references/ui_ref_01.png`처럼 로컬 폴더에 두고 Claude Code에게 분석을 요청할 수 있습니다.

- 캡처는 **관찰용 로컬 입력**입니다. GitHub·Vercel·패들렛에 올리지 않습니다.
- 화면의 로고·아이콘·글꼴·카피·이미지·차트·레이아웃을 그대로 재현하지 않습니다.
- 결과물은 내 데이터, 내 문장, 원본 CSS/SVG와 자체 차트로 다시 만듭니다.
- 실제 서비스에 쓰기 전에는 해당 서비스의 이용약관·저작권·상표권·디자인 권리를 별도로 확인합니다.

```text
[레퍼런스 캡처 분석]
references/ui_ref_01.png는 수업 중 내가 직접 캡처한 관찰용 자료다. 이 파일을 공개하거나 코드·배포물에 넣지 마.
이미지에서 복제하면 안 되는 로고·아이콘·문구·이미지·고유 화면 요소를 먼저 표시해.
그 다음 정보 위계 / 사용자가 먼저 보는 내용 / CTA 위치 / 입력 순서 / 정상·빈값·오류 상태 표현만 추출해.
내 docs/lean_canvas.md, persona.md, journey_map.md, requirements.md에 맞는 **원본** UI 원칙 3개와 AIDA 랜딩 설계안을 docs/ui_design.md에 추가해.
원본 화면의 색·문구·배치를 그대로 따라 하지 말고, 각 원칙이 내 R-01·R-02·R-03과 어떻게 연결되는지 적어.
```
