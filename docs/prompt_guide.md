# 단계별 프롬프트 가이드 — 블록으로 명령하기

> STAR-T가 실제 서비스 검증에 써 온 방식입니다. 좋은 명령은 길이가 아니라 **구조**가 다릅니다.
> 각 단계의 전체 명령은 `START.html`에서 복사할 수 있습니다. 이 문서는 **틀**과 **단계를 가로지르는 명령**을 모았습니다.

## 1. 명령 틀 (9블록) — 내 명령을 이 순서로 씁니다

| 블록 | 쓰는 것 | 빠지면 생기는 일 |
|---|---|---|
| **[역할]** | AI가 맡을 전문가와 태도 | 말투·깊이가 매번 달라짐 |
| **[목표]** | 이번 단계가 끝났을 때의 상태 한 문장 | 필요 없는 일까지 함 |
| **[답변 방식]** | 한국어 · 쉬운 말 · 표 먼저 | 새 대화에서 영어로 답하거나 설명이 길어짐 |
| **[입력]** | 먼저 읽을 파일·자료 | 이전 결과를 무시하고 새로 지어냄 |
| **[진행]** | 번호 붙인 순서 · 한 번에 하나씩 할 것 | 한꺼번에 만들어 어디서 틀렸는지 모름 |
| **[출력]** | 파일 이름과 표의 열 | 결과가 흩어지고 다음 단계가 못 읽음 |
| **[저장 전 자가 점검]** | ✅/❌로 확인할 기준 3~4개 | 틀린 결과를 완료로 저장 |
| **[지킬 것]** | 추측 수치·가짜 출처·키·개인정보·투자 권유·범위 밖 수정 금지 | 그럴듯한 거짓·보안 사고 |
| **[끝나면 보고]** | 바꾼 파일 · 실제 확인한 것 · 확인 못 한 것 · 다음 단계 | 「완료했습니다」만 남음 |

**빈 틀 (복사해서 채우기)**
```
[역할] 너는 ____야.
[목표] ____ 상태가 되게 한다.
[답변 방식] 한국어로, 쉬운 말로, 표를 먼저 쓰고 설명은 짧게.
[입력] ____ 파일을 먼저 읽어.
[진행]
1. ____
2. ____
3. ____
[출력] ____.md — 표 열: ____ / ____ / ____
[저장 전 자가 점검] 아래를 ✅/❌로 보여주고 ❌가 있으면 고친 뒤 저장해: ____ · ____ · ____
[지킬 것] 추측한 수치·출처를 만들지 않는다 · API 키·비밀번호·개인정보를 묻거나 쓰지 않는다 · 투자 권유 문장을 쓰지 않는다 · 말한 파일 밖은 수정하지 않는다.
[끝나면 보고] ① 저장·수정한 파일 ② 실제로 열어 확인한 것 ③ 확인하지 못한 것 ④ 다음 단계 한 줄.
```

## 2. 가장 위험한 가정 찾기 (주제 정할 때)

```
[역할] 린 스타트업 코치.
[목표] 내 아이디어에서 가장 먼저 확인할 가정 1개를 고른다.
[입력] docs/topic.md
[진행]
1. 이 아이디어가 성립하려면 참이어야 하는 가정을 4축으로 뽑아: 불편이 실재하나 / 사람들이 이 방법을 쓸까 / 오늘 만들 수 있나 / 법·제도·신뢰 문제는 없나.
2. 가정마다 위험도(틀리면 얼마나 치명적인가)와 불확실성(지금 얼마나 모르는가)을 상·중·하로.
3. 둘 다 높은 가정 1개와, 그것을 가장 싸게 확인할 방법 1개를 제안해.
[출력] 표(축 · 가정 · 위험도 · 불확실성 · 확인 방법) + 선택한 가정
[저장 전 자가 점검] 가정이 검증 가능한 문장인가 · 확인 방법이 이번 주 안에 가능한가 · 추측을 사실로 쓰지 않았는가
[지킬 것] 조사 결과·수치를 지어내지 않는다.
[끝나면 보고] 선택한 가정과 이유 한 줄.
```

## 3. 내 전제를 반박해 보기 (린캔버스 Lv2)

```
[역할] 반대 입장의 심사위원. 내 서비스가 필요 없다는 증거를 먼저 찾는다.
[목표] 린캔버스의 핵심 전제 중 틀린 것을 찾아 고친다.
[입력] docs/lean_canvas.md · docs/evidence.md
[진행]
1. 핵심 전제 3개를 뽑아.
2. 각 전제를 이 순서로 반박해: 이미 무료로 같은 걸 해주는 공공·민간 서비스가 있나 / 제도가 내가 생각한 방식으로 작동하나 / 같은 사용자를 노리는 경쟁 서비스가 있나.
3. 반박 근거는 링크를 열어 확인한 것만 쓰고, 반박된 전제의 수정안을 제안해.
[출력] 표(전제 · 반박 근거 · 링크 · 판정: 유지/수정/폐기 · 수정안)
[저장 전 자가 점검] 링크를 다시 열어 대조했는가 · 반박이 없으면 「반박 못 찾음」으로 정직하게 적었는가
[지킬 것] 추측으로 경쟁사·제도를 만들지 않는다.
[끝나면 보고] 수정·폐기한 전제와 린캔버스에 반영할 칸.
```

## 4. 사용자 인터뷰 (수업 후)

**질문 설계**
```
[역할] 사용자 리서처. 칭찬이 아니라 과거 행동을 듣는다.
[목표] 가장 위험한 가정 「____」을 확인할 인터뷰 질문 7개를 만든다.
[진행]
1. 최근 실제 사례를 묻는 질문으로 시작해("마지막으로 ○○했을 때 어떻게 하셨어요?").
2. 지금 어떻게 해결하는지, 돈이나 시간을 얼마나 쓰는지 물어.
3. 내 아이디어는 설명하지 말고, "쓰실 건가요?" 같은 미래 질문은 넣지 마.
[출력] 질문 7개 + 피해야 할 질문 3개(이유 포함)
[저장 전 자가 점검] 미래·가정형 질문이 없는가 · 유도 질문이 없는가 · 개인정보를 묻지 않는가
[끝나면 보고] 인터뷰 대상 조건 한 줄.
```

**메모 분석**
```
[역할] 사용자 리서처.
[목표] 인터뷰 메모에서 가정을 판정한다.
[입력] 인터뷰 메모(이름·연락처는 지운 상태)
[진행]
1. 불편의 강도(강/약) · 현재 해결 방법 · 돈·시간을 쓰는지 · 내 가정과 반대되는 신호를 뽑아.
2. 메모에 있는 문장만 근거로 쓰고 해석은 따로 표시해.
[출력] 신호표 + 판정(맞다 / 판단 보류 / 틀렸다) + 다음에 확인할 것 1개
[저장 전 자가 점검] 근거 문장이 메모에 실제로 있는가 · 반대 신호를 빠뜨리지 않았는가
```

## 5. AI의 「완료」를 믿기 전에 (구현 단계 어디서나)

```
[역할] 검수자.
[목표] 방금 완료라고 한 작업이 실제로 확인됐는지 가린다.
[진행]
1. 완료라고 한 항목마다 확인 방법을 적어: 파일을 열었나 / 어떤 입력으로 무엇이 나왔나 / 누가 확인했나.
2. 실행하지 않은 확인은 미확인으로 바꿔.
[출력] 표(항목 · 확인 방법 · 결과 · 확인됨/미확인)
[지킬 것] 확인하지 않은 것을 통과로 쓰지 않는다.
```

## 6. 배포 전 보안 점검 (배포할 때마다)

```
[역할] 보안 점검 담당. 수정하지 않고 찾기만 한다.
[목표] 공개해도 안전한 파일만 올린다.
[입력] 프로젝트 폴더 전체
[진행] 아래 8항목을 점검해 표로 보여줘:
1. API 키·토큰·비밀번호로 보이는 문자열
2. 개인정보(이름·전화·이메일·계좌)
3. .env·실제 시세 파일·원문 PDF 등 올리면 안 되는 파일
4. 입력값을 외부로 보내는 코드
5. fetch·CDN·외부 글꼴 사용
6. index.html 위치와 파일명 대소문자
7. 결제·광고·투자 권유 문구
8. 파일 수와 가장 큰 파일
[출력] 표(항목 · 발견 여부 · 위치 · 고치는 방법)
[지킬 것] 발견한 키·개인정보 값을 화면에 그대로 다시 출력하지 않는다(앞 4자리만).
[끝나면 보고] ❌ 항목과 먼저 고칠 순서.
```
→ 배포 순서는 `docs/guides/vercel_free_deploy.md`

## 7. 발표 전 주장 검수

```
[역할] 발표 코치이자 주장 검수자.
[목표] 핵심 주장 1개와 확인된 증거만 남긴다.
[입력] docs/lean_canvas.md · docs/evidence.md · docs/deploy_check.md · 배포 주소
[진행]
1. 핵심 주장 한 문장 + 뒷받침 증거 최대 4개(작동 화면 / 확인된 R-ID / 근거 자료 / 배포 주소).
2. 소개 문장을 가능(확인됨) / 제한(조건 필요 · 조건 문구 제안) / 금지(근거 없음·과장·투자 권유)로 분류.
3. 45초 대본: 문제 15초 · 동작 20초 · 한계와 다음 개선 10초.
[출력] 주장·증거표 + 분류표 + 대본
[저장 전 자가 점검] 금지 문장이 대본에 없는가 · 증거가 모두 확인된 것인가
```

---

**이 가이드에서 지키는 것** — 키·비밀번호·개인정보는 채팅과 파일에 넣지 않습니다 · AI의 「완료」는 확인이 아닙니다 · 근거 없는 수치·효과·투자 권유 문장은 쓰지 않습니다.
