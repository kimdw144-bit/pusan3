# 사업계획서 · M5-07에서 완성하고 M6에서 실제 결과만 보완

> 이 문서는 마지막 25분에 새로 쓰지 않습니다. **M5-07에서 Lean Canvas·MVP·RICE까지 포함한 MD를 완성하고 NotebookLM에 바로 명령합니다.** M5-08·M6-01·M6-02가 끝나면 테스트·배포의 실제 결과만 해당 칸에 덧붙입니다. MD 자체가 제출 정본입니다.
>
> 문장마다 성격을 표시합니다. `[사실]`은 값·기준 시점·원문 링크가 있는 내용, `[가설]`은 아직 고객에게 확인하지 않은 내용, `[검증]`은 실제로 눌러 본 테스트·인터뷰·설문 결과입니다. 숫자·고객 수·매출·시장 규모를 지어내지 않습니다.

## 이 순서로 쓰는 이유

사업계획서는 좋은 아이디어를 길게 소개하는 글이 아니라, **근거 → 고객 문제 → 해결 방법 → 작은 실행 → 고객 검증 → 다음 결정**이 연결되는 문서입니다. Lean Canvas의 9칸을 모두 쓰되, 각 칸을 고객·데이터·MVP·측정 계획으로 연결합니다. 그래서 구현 전에 8개 장의 MD를 만들고, 실제 테스트 결과가 나오면 검증 상태만 바꿉니다. NotebookLM은 이 정본 MD를 시각화하는 선택 도구입니다.

## ④ 고객·TAM/SAM/SOM·가치 제안

- 고객군: 넓은 표현 대신, 첫 고객의 직업·상황·지역·필요를 좁게
- TAM: 같은 문제에 돈·시간을 쓰는 전체 범위 — **산식·기간·원문 링크**, 없으면 `[가설]`으로 빈칸
- SAM: 현재 제품·지역·채널·역량으로 실제 제공 가능한 부분 — TAM과 같은 상품·기간 기준
- SOM: 정한 기간에 채널 접근성·전환·수행 가능 수 중 작은 값으로 잡은 첫 확보 범위 — 산식 또는 `[가설]`
- 고유 가치 제안(UVP) 한 문장:
- 현재 확인된 경쟁 우위 / 아직 검증할 우위:
- 출처: `lean_canvas.md` · `data_sources.md` · 필요 시 공개 시장 리서치 링크

## Claude Code에 보낼 명령 · M5-07에서 MD 완성

```text
[역할] 초기 사업계획서 편집자. Lean Canvas의 9칸을 고객 검증 계획까지 연결한다.
[입력] docs/data_sources.md, topic.md, lean_canvas.md, persona.md, journey_map.md,
        mvp_rice.md, requirements.md, qa_scenarios.md, research_guide.md,
        docs/business_plan.md 양식
[목표] MVP·RICE까지 확정한 지금 business_plan.md의 ①~⑧을 채워 제출 가능한 MD 정본을 만든다.
[진행]
1. 각 문장에서 [사실] / [가설] / [검증]을 구분하고, 숫자는 값·단위·기준 시점·원문 링크가 있을 때만 [사실]로 쓴다.
2. Lean Canvas 9칸이 ①~⑧ 어디에 반영되는지 연결표를 완성한다. 비어 있는 칸은 지어내지 말고 [가설] 또는 [리서치 필요]로 둔다.
3. TAM·SAM·SOM은 같은 상품·기간·단위로 산식이 가능한 경우에만 적는다. 산식이 없으면 고객 범위 정의와 필요한 원천만 적는다.
4. 채널·수익·비용·핵심 지표는 첫 고객 검증 계획으로 쓰며, 확인 전 수치·매출을 만들지 않는다.
5. 지금은 구현 결과를 만들지 않는다. ⑤·⑧에는 [검증 예정] 칸을 남기고, M6-02 뒤 test_log.md·deploy_check.md의 실제 결과가 생길 때만 보완한다.
6. 저장한 business_plan.md 하나를 NotebookLM에 바로 올릴 수 있도록, 아래 NotebookLM 명령을 복사해 함께 보여 준다. PDF 생성은 기다리지 않는다.
[출력] docs/business_plan.md. 바꾸기 전·후와 [사실]/[가설]/[검증] 개수를 표로 보여 준 뒤 저장한다.
```

## NotebookLM에 넣을 명령 · M5-07 직후 또는 수업 후 선택

```text
이 business_plan.md를 유일한 사실 원천으로 사용해 한국어 발표 슬라이드 10장 이내를 만들어줘.
장 순서: 1 현황 데이터 → 2 문제·기존 대안 → 3 페르소나·저니 최저점 →
4 고객·TAM/SAM/SOM·UVP → 5 MVP·RICE → 6 제품 화면·요구사항 →
7 채널·마케팅 실험 → 8 수익·비용 가설 → 9 핵심 지표·마일스톤 → 10 한계·다음 검증.
각 장은 한 메시지·시각 요소 하나(원본 데이터를 바탕으로 한 표·흐름도·간단 차트)만 사용해.
새 숫자·고객 수·매출·시장 규모·사례를 만들지 말고, [가설]과 [검증] 라벨을 그대로 유지해.
링크가 없는 내용을 사실처럼 쓰지 말고, 출처가 필요한 장에는 원문 기관명을 작게 적어.
브랜드·타사 로고·화면을 복제하지 말고, 깨끗한 원본 도형과 차트로 구성해.
```
