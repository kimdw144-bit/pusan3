# 피드백 반영 기록 (M5-06)

> 강사·동료·AI의 피드백은 **정답이 아니라 가설**입니다. 근거와 내 서비스 맥락을 보고 반영·보류·미반영을 선택합니다. 다만 최종 판단도 고객의 실제 행동 앞에서는 가설입니다. 빠르게 동작하는 MVP를 보여 주고, 고객의 사용·거절·완료 행동으로 다시 검증합니다.

## 판단 순서

1. 피드백이 가리키는 문장·칸·사용자 행동을 확인합니다.
2. 이미 가진 데이터·인터뷰·저니맵 근거와, 내 직관·현장 맥락을 구분해 적습니다.
3. 반영하기 전과 후를 나란히 봅니다.
4. 고객에게 확인할 행동과 GO / 보류 기준을 정합니다.

> 애자일의 핵심은 계획을 버리는 것이 아니라, 작동하는 결과를 자주 보여 주고 고객 반응에 따라 계획을 조정하는 것입니다. AI는 구현 속도를 높이지만 고객 문제·요구사항·테스트를 대신 검증하지는 않습니다.
